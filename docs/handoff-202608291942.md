### Two deliberate divergences from the ticket

Both are recorded in the ticket next to the original text, so it reads as a record rather
than a plan that drifted:

- **Item 2** said *replace* `_DISABLED_BY_CLASS`. It is **layered above** it instead, so the
  hand-curated dict remains the final fallback and the worst case degrades to today's
  behaviour rather than to no filtering. A class cell is only authoritative when at least one
  strategy clears the 30-signal threshold — a swept-but-thin cell falls through rather than
  returning an empty disabled set (which would drop the safety net by another route).
- **Item 5** said source `n`/`base_win_rate` per class. That would replace group-specific
  evidence with a class average and lose information. Changed the shrink **target** instead:
  `compute_derived()` shrinks toward the (model, class) base win rate rather than a flat 0.5.
  With no class prior the arithmetic is identical to before.

### Subagent regressions — read this before delegating again

Two agents edited `strategy/kairos_signals.py` in sequence. The second silently clobbered the
first's work **twice**:

- the `model_path` pass-through at the `resolve_disabled_strategies` call site, and
- a monkeypatched lambda's signature in `test_signals_report.py`.

The first is the serious one: `resolve_disabled_strategies` would have accepted a `model_path`
nobody passed, leaving the gate permanently resolving as `stage="base"`. **Item 1 would have
been inert while appearing complete, and no test would have failed.** Both were found by
reading diffs against the agents' reports, not by the suite.

Mitigations for next time: never run two agents against the same file even in sequence
without re-reading the diff afterwards; treat an agent's "I made change X" as a claim to
verify, not a fact.

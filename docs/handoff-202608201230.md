## Key decision: 1h, not literal 12h

Neither yfinance nor `exchange_calendars` (`kairos/calendars.py`'s
`_INTERVAL_MINUTES` tops out at `1h`/60min) recognize a native 12h or 3h
bar. Confirmed with Baz during planning: target `1h` instead — it already
has a documented playbook (`docs/playbooks/hourly-signals.md`), a
`--include-hourly` flag in `kairos_weekly_discovery.py`, and interval-keyed
predcache/finetune-registry plumbing in place. Also confirmed: universe
screening and correlation grouping are to be **fully recomputed from native
1h bars**, not reuse 1d-derived liquidity stats (E1/E2 scope).

## What was done this session

### E0 — Shared plumbing hardening (see DESIGN_DOC_multi_interval_1h.md §2 for detail)

1. **Sharpe annualization** — replaced four hardcoded `sqrt(252)` call sites
   (`kairos_orchestrator.py` ×2, `kairos_strategies.py`, `kairos_backtest.py`)
   with a new shared `bars_per_year(interval)` helper in `kairos_backtest.py`.
   `1d` still resolves to exactly `252` — bit-identical.
2. **`BARS_PER_DAY` consolidation** — three duplicated dicts merged into one,
   in `kairos_backtest.py` (avoids an import cycle: `kairos_strategies.py`
   already imports `kairos_orchestrator.py`, so the shared constant can't
   live in either of those).
3. **Signals-cache `as_of` truncation** — `kairos_signals.py`'s
   `_signals_cache_key` used to collapse every intraday call in a day onto
   one calendar-date cache key (fine for `1d`, silently stale for `1h`).
   New `_cache_as_of_value(now, interval)` keeps the date-only key for
   daily-or-coarser intervals, floors to the bar boundary for intraday ones.
4. **Correlation-stage `MAX(run_id)` interval leak** — `run_stage_correlation`
   and `_group_symbols_from_db` (`kairos_pipeline.py`) used to grab the
   globally most recent universe/correlation run regardless of requested
   interval. Both now join through the `runs` table's `interval` column.
   This one was live-caught by existing tests once fixed — four tests in
   `test_pipeline_auto.py` were bypassing `start_run` in their fixtures
   (inserting straight into `universe_screen`), which the interval-scoped
   query correctly no longer tolerates. Fixed the fixtures to insert
   matching `runs` rows rather than loosening the query.

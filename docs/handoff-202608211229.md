- **Batch operational hiccup #1 (self-inflicted, now understood)**: JTO-USD, one of the 3 originally-failed 1h candidates being retried, actually trained successfully for real (~40-50 min, checkpoint saved to `models/finetuned/1h__JTO-USD/final_model`) but then crashed with `[Errno 32] Broken pipe` (visible in `models/finetuned/1h__JTO-USD/metadata.json`) right as it tried to move into the backtest/verdict phase. Root cause: earlier in this session, killing the first (buggy) batch script instance with `pkill` orphaned JTO-USD's `kairos_pipeline.py --stage finetune_next` subprocess (its own further child, `uv run finetune`, wasn't matched by the pkill pattern and kept running legitimately) — but once the orphan's original stdout reader (the dead parent) was gone, its later `print()` calls raised `BrokenPipeError`, which the code's own exception handler correctly caught and marked the row `status='failed'`. **JTO-USD's registry row (id=178) is stuck at `failed` with a real, trained-but-never-evaluated checkpoint on disk.** Retrying means re-training from scratch (no code path to resume just the backtest step from an existing checkpoint) — deliberately deferred rather than block the batch; flagged to Baz as a mistake, not hidden.
- **Batch operational hiccup #2**: the GPU-idle pre-check (`is_gpu_idle`, default 10% utilization threshold) was blocking every candidate almost indefinitely, because this machine's GPU baseline idles at 20-45% from some unrelated desktop process (confirmed low memory use, ~168MB, so not a real competing GPU job) — the 10% threshold is simply too strict for this machine's actual "idle." First noticed as the batch script silently treating "GPU busy" skips as completed cycles (fixed earlier, before this handoff segment, with a wait-and-retry loop + 60-minute give-up cap, per Baz's explicit request). Fully resolved this segment by adding `--skip-idle-check` to the batch script's `finetune_next` invocations — safe because the separate `GpuLock` mechanism still serializes actual training against other real GPU jobs; this only skips the "wait for a quiet moment" heuristic, not real concurrency safety.
- After both fixes, the batch is running cleanly: COST completed a full real cycle in 710s (~12min) — **legitimately REJECTED** (base viable_count=16 mean_sharpe=1.81 vs finetuned viable_count=8 mean_sharpe=18.00; the accept gate requires `ft_count > base_count` OR a tie with higher mean, neither held, so reject is correct, not a bug).

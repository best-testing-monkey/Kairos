# E7-S21 — Closure computation pipeline (reuses BacktestEngine's private exit/PnL primitives)

**Goal:** For each `papertrade_signals` row needing it, resolve and persist its isolated outcome (`papertrade_signals_closure`), reusing `BacktestEngine`'s predictor-free exit/PnL logic.

**Context — read §3.3 of the design doc IN FULL before writing any code, it corrects a real mistake from an earlier draft:**
- `docs/tickets/DESIGN_DOC_offline_signal_replay.md` §3.3 explains exactly why `BacktestEngine.run()` itself is NOT reusable here: `run()`'s job is to *generate* a signal (decide whether/where to enter) via `self.predictor.predict(history)` + `router.route(...)`, but this pipeline already has the signal — `entry`/`stop`/`target`/`direction` are sitting in `papertrade_signals`, unpacked from an already-computed `signals_cache` row. The reusable pieces are `BacktestEngine._check_exit(position: dict, bar: pd.Series) -> tuple[float|None, str|None]` and `BacktestEngine._calculate_pnl(position: dict, exit_price: float) -> float` — both private, both take a GIVEN position and resolve its outcome with no prediction step at all (this is true regardless of whether predictions are cached or not — don't reason about this as "avoiding slow GPU calls," reason about it as "we already have the decision, we don't need to re-derive it"). Read `strategy/kairos_backtest.py`'s `BacktestEngine.__init__`, `_check_exit`, `_calculate_pnl` (~lines 1898-2025) directly and confirm current signatures against source — do not trust this ticket's or the design doc's paraphrase as permanently accurate, code may have moved since 2026-08-08.
- A `BacktestEngine(predictor=None, fee_pct=..., slippage_pct=...)` instance can call `_check_exit`/`_calculate_pnl` safely as long as `.run()`/`.run_strategy_comparison()` are never invoked on it.
- Read `strategy/kairos_signal_replay.py` (own module — outputs of E6-S17 `_ensure_signal_replay_tables`, E7-S19 `resolve_interval_for_signal`, E7-S20 `max_adverse_excursion_pct`).
- Read the installed `phantom` package's `price_cache.get_price_data` (same reference as E7-S19) for fetching the forward bars once the interval is resolved.

**Acceptance criteria:**
- [ ] `compute_closure(conn, signal_row, interval_ladder: list[str], fee_pct: float, slippage_pct: float, db_path: str, engine_version: str) -> None` (or return a small result object — implementer's call, document choice):
  - Calls `resolve_interval_for_signal(...)` (E7-S19). If it returns `None`: write a `papertrade_signals_closure` row with `resolved=0` and every other column `NULL` except `engine_version`/`computed_at` (per DESIGN_DOC §3.2 — disqualified is a real, present row marked unresolved, not a silently absent one — confirm this against §3.1's schema comment, which says "every other column is NULL when resolved=0").
  - Otherwise: fetches forward bars via `price_cache.get_price_data` at the resolved interval starting from the signal's `entry_datetime` (from `papertrade_signals`, via E6-S18's populated row).
  - Constructs `BacktestEngine(predictor=None, fee_pct=fee_pct, slippage_pct=slippage_pct)`, builds a `position` dict (`direction`, `entry`, `stop`, `target`) from the signal row, and walks the fetched bars ONE AT A TIME calling `_check_exit(position, bar)` until it returns a non-`None` exit (or bars are exhausted — treat exhaustion as a disqualification too, same as the interval-resolution failure case, and document this choice).
  - In the SAME bar walk, also computes `max_adverse_excursion_pct` (E7-S20) — one loop, both things tracked, per DESIGN_DOC §3.3's explicit guidance not to do a separate pass.
  - On resolution, calls `_calculate_pnl(position, exit_price)` for the raw PnL, converts to `pct_profit` (matching `Trade.pnl_pct`'s convention: `pnl / (entry_price * size)`), and writes a `resolved=1` closure row with `interval_used`, `pct_profit`, `max_drawdown_pct`, `trigger_datetime` (=entry_datetime), `exit_datetime`, `exit_reason`, `engine_version`, `computed_at`.
- [ ] `compute_closures_for_window(conn, start_date, end_date, interval_ladder, engine_version, fee_pct=0.001, slippage_pct=0.0005, db_path=...) -> int` (returns count computed): iterates every `papertrade_signals` row with `as_of` in the window that has NO closure row yet, OR whose existing closure row's `engine_version` does not match the current `engine_version` argument, calling `compute_closure` for each — this is the cache-aware / `engine_version`-bump-forces-recompute behavior from DESIGN_DOC §3.1.
- [ ] Unit tests: mock `price_cache.get_price_data` to return synthetic bars for a known `entry`/`stop`/`target`/`direction`, verify `pct_profit`/`exit_reason`/`max_drawdown_pct` match a HAND-COMPUTED value (same discipline as `test_leverage_off_matches_pinned_baseline`'s worked derivation this session). Separately test: the disqualification path (mock returns empty for every interval in the ladder); the bars-exhausted-without-resolving path; the `engine_version`-mismatch triggers recompute (call `compute_closures_for_window` twice with different `engine_version` values, assert the second call recomputes).

|---|---|---|---|

| mini | 925s (17/20 groups — not comparable) | 370.5s | 550.0s |

Phase 2 is identical across a 25x parameter range, exactly as the architecture
predicts. All model difference is in phase 1, which is ~half the wall clock.

## What went wrong (worth knowing before repeating it)

- **Four subagents stalled** waiting on backgrounded pytest despite explicit
  foreground instructions in every prompt. The repo's suite takes ~480-525s,
  exceeding the Bash timeout, so the harness auto-backgrounds it and the agent
  then waits for a notification instead of reporting. A nudge recovers each time.
  Consider running the suite yourself rather than delegating it.
- **Orphaned pool workers.** `ProcessPoolExecutor` children survive a killed
  parent. Eight ran for over an hour, held GPU, caused an OOM, contaminated every
  timing measurement, and double-swept 6 groups. After any kill, check
  `ps -eo pid,ppid,cmd | grep -E 'run_model_parallel|kairos_strategies' | awk '$2==1'` —
  `nvidia-smi` alone won't show them if they're idle between chunks.
- **`pkill -f <pattern>` matches its own shell** and killed the session's own
  command three times. Kill by explicit PID.
- **`GROUPS` is a bash built-in readonly array** (user GIDs). Assigning it is
  silently ignored and `$GROUPS` expands to `1000`.
- **Timing measured under load is worthless.** Several conclusions were drawn and
  retracted this session because a benchmark ran while something else used the
  box. `scripts/benchmark_models.py` exists to prevent that; use it rather than
  ad-hoc timing.

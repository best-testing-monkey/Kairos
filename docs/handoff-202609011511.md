## Lessons worth not relearning

- **Compute import reachability before editing during a sibling's sweep.** The sweep
  runs `kairos_strategies.py`, which reaches only 17 of 28 `strategy/` modules —
  `allocation.py`, `kairos_signals.py`, `kairos_papertrade.py`, `kairos_pipeline.py`
  and `signal_selection.py` are outside the closure and were safely edited through a
  6-hour sweep. Freezing the whole repo would have been over-correction; guessing
  would have been the 2026-08-29 disaster. Saved to memory as
  `feedback_import_reachability_before_editing.md`. The sibling independently
  re-verified the claim before relying on it — the right response to receiving one.

- **`pkill -f <pattern>` matches its own shell.** Did it again this session despite it
  being documented in the previous handoff. Kill by explicit PID.

- **Monitor the worker, not the wrapper.** Two heartbeats in a row reported a
  ~2–3MB / 0-CPU process as "the job" — first the `timeout` wrapper, then this
  session's own watcher shell, because `pgrep -f "python3 .*papertrade"` matches any
  shell whose command line contains that string. Both would have reported "alive"
  through a total wedge. Anchor on the venv binary: `[.]venv/bin/python3`.

- **A new regime must be added to every cache keyed on the components it shares.**
  Two were missed on the first pass and both were real. If a third regime is ever
  added, grep for cache keys before assuming it is only a flag.
